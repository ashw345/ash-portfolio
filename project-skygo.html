SKY GO 短视频创作

为英国流媒体平台 Sky 设计的短视频创作链路——让看剧的人成为创作者。

团队在我进入之前已经做过第一版创作功能：只有一个从主页新建的入口，创作和看剧是并排的两件事，也还没有 AI 换脸这类玩法。这一轮我们要往前推一步——新增两个入口，让创作能从观看里自然长出来。而我接手的，恰恰是第一版就已经存在的那条主页创建链路：它不缺功能，缺的是结构。

我负责 三入口串联架构 / 主页入口优化
时长 2024.04 — 2024.05
成员 Danny Xu / Jessie Shen
工具 Figma / Photoshop
Scope 这是一个三人小组课题，我主要负责 UX 部分：把三个创建入口在产品里串成一套完整体验——决定每个入口切进主干的位置、共用哪段流程、在哪里可以提前收尾；以及第一版就已存在的「主页新建」入口的重做。视觉与部分界面由组内其他同学完成。
Users & Problem

看剧的人想创作，但路太长

目标用户是 Z 世代的流媒体重度用户。他们看完一部剧后有两个诉求：想看到别人围绕这部剧做的衍生内容，也想自己做一条——但前提是「这件事得足够容易，人人都能发」。对着第一版走一遍流程，问题集中在三处。

01 创作门槛高 创建短视频的流程不够直观清晰，步骤分散在多个位置。对于只是想「随手做一条」的普通用户，这些门槛足以让他中途放弃。
02 入口只有一个 创建视频只出现在导航栏，缺乏其他触达途径。而创作动机最强的时刻其实是「刚看完一集」的那一秒，那个时候用户在观看页，不在导航栏。
03 同好找不到彼此 短视频以「视频技术类型」区分，而不是以影视作品区分。喜欢同一部剧的人没有聚集的地方，创作出来的内容也就找不到对的观众。
Persona

我们在为谁设计

目标用户锁定 Z 世代——1990 年代中后期到 2010 年代初出生的这一代人。他们不是把「看剧」当终点的观众，而是习惯了在内容周围二次表达的一代。

Characteristic 他们对工具没有畏惧，对差异有耐心。 技术娴熟 在数字时代长大，对各类设备与社交平台的使用高度熟练——这意味着复杂不是问题，繁琐才是。 包容开放 更能接受性别、性向、种族与信仰上的差异，也更愿意看见不同的表达方式出现在同一个内容社区里。
Demands 他们要的是一个能基于 Sky 内容互动、并且做得出东西的社区。 题材相关 短视频要和 Sky 的影视内容真正挂上钩，而不是一个内容无关的通用创作工具。 玩法多样 需要足够多的视频类型，让用户能真的「进到剧情里去」，而不是只能套一个固定模板。 上手容易 足够简单到人人能发，但编辑器本身要够完整——这两条看似矛盾，正是编辑器设计上最难拿捏的地方。
Baseline

我接手时的第一版

要说清楚这一轮做了什么，得先说清楚起点。第一版已经能创建短视频，但它把「创作」当成一个独立功能塞在主页里，跟用户正在看的内容毫无关系；而进去之后的那条路，问题不在缺功能，在于组织方式。

第一版从主页新建视频的完整链路，以及我在走查时标出的问题点。

第一版有什么
  • 只有一个创建入口——从主页新建，观看页里没有任何创作的口子。
  • 没有 AI 换脸这类玩法，用户没法把自己放进剧情里。
  • 特效被切成「Deep Fake / Real Fantasy / Reels」三套各自独立的场景，入口分散、逻辑还不一样。
  • 编辑是相机优先的：像 Instagram、抖音那样鼓励用户举起手机现拍。
我走查时标出的问题
  • 整条流程冗余，走完要经过好几个功能重叠的页面。
  • 特效命名让人猜不到下一步：「Deep Fake」「Real Fantasy」这些词没告诉用户点进去会发生什么。
  • 点击「创建视频」缺少视觉反馈，用户不确定自己有没有点到。
  • 内容选择页吸引力不足，是一个纯列表，看不出可以拿它做什么。
  • ICON 设计不统一，同一屏里的图标风格对不上。
Solution

把观看和创作接成闭环

三条措施合起来是一个环：在观看页触发创作，用简易编辑器完成合成，发布时标注剧集 Tag，这条视频又回到剧集页面被下一个人看到——看剧的人变成创作者，创作的内容再把人带回剧集。

闭环图占位
images/skygo-loop.png
观看剧集 → 合成 → 发布 → 观看短视频 → 回到剧集
剧集 + 短视频 在影视观看页新增创作入口，点开是四个选项——AI 换脸、实时换脸、叠加特效、录制，从剧集里直接引导用户参与创作，让入口出现在动机产生的地方。
简易编辑器 原设计把「深度换脸」「真实幻想」「Reels」做成三个各自独立的创作场景，入口分散、逻辑还不一样。我们把它们合并成一条线：选模板快速生成，各类特效收进同一个简易编辑器里调整。
影视 Tag 在影视剧集下新增短视频页，按作品而不是按特效类型聚合，同好用户终于有了聚集的地方，闭环也在这里合上。
Architecture

三个入口，一条主干

这一版把创建入口从一个扩到三个。但三个入口不是三条各自为政的路——它们是同一条流水线上的三个切入点，切在哪里，取决于用户进来时系统已经知道多少上下文。这条串联架构是我在这个项目里的主要产出。

完整使用流程：三个入口分别切入「选择影视 → 选择模版片段 → 选择特效 → 录制 → 细节调整 → 上传」这条主干的不同位置，最后汇于同一个发布步骤。

入口 2 · 我优化 主页新建 第一版唯一的入口。用户带着明确意图进来，什么上下文都没有，所以要从头问起。
已知上下文 无 切入位置 主干最前端 · 选择影视 用户状态 我今天就是想做条视频
入口 1 · 新增 影视观看页 正在看的这一集就是素材，选片和选模板两步可以直接省掉。
已知上下文 影视、片段 切入位置 主干中段 · 选择特效 用户状态 这段太好笑了，我想玩一下
入口 3 · 新增 拍同款 影视、模板、特效全部从那条视频继承，用户几乎不用做任何选择。
已知上下文 影视、模板、特效 切入位置 主干末端 · 细节调整 用户状态 他这条不错，我也来一个
判断一 · 深浅不是不统一，是上下文差异的结果 三个入口的流程长短差很多，但这不是设计没对齐——是「已知多少就少问多少」的必然结果。最典型的是观看页：换完脸之后可以直接发布，也可以选择进编辑器细调。之所以给出「不进编辑器」这个选项，是因为用户此刻正在看剧，把他拉进一个完整编辑器就等于打断观影连贯性——创作不该以牺牲正在进行的观看为代价。
判断二 · 主页入口看似孤立，它的职责是启动循环 观看页与拍同款能自己转成一个环：看剧 → 创作 → 发布 → 别人刷到 → 拍同款 → 再发布。主页新建不在这个环里，但这恰恰是它存在的理由——如果所有入口都依赖「你已经在消费内容」，新用户就永远进不来：想创作得先刷到别人的作品，而别人的作品又来自创作。主页新建是唯一不需要前置条件的入口，负责把人放进环里。它也不是完全断开的，短视频页可以回到主页，只是需要主动导航——这个「弱连接」是刻意的，它服务的是主动意图，不该被内容推着走。

手机、平板、桌面三端都做了

SKY GO 不只是一个手机 App。同一套创作与观看体验要在三种断点下都站得住——平板端横屏观看时把编辑入口收进顶部图标栏，桌面端则展开成完整的网页布局，播放器、剧集选集与热门短视频并排陈列。

Iteration

我重做了什么

我负责的这条链路在第一版里已经存在，所以我的产出不是「多一个功能」，而是把三套割裂的特效场景重新组织成一条线：统一入口、按内容而不是按技术命名步骤、把编辑器换成贴合影视片段的模型。下面两组对比是其中判断成本最高的两处——它们看的不是执行，是为什么第一版看起来没错、对这个产品却是错的。

Retrospective

复盘与局限

这个项目没有上线，也就没有任何数据能证明这些判断是对的。与其在这里放一组不存在的指标，不如把缺口写清楚——以及如果重做一次，我会先补哪几件事。

Gap 01 缺少可用性验证。整条创建流程只在组内走查过，没有找真实用户跑一遍。最该验的是第 3 步——模板到底能不能让不会剪辑的人独立完成一条视频。
Gap 02 闭环没有被数据检验。「发布必须标 Tag」是整个闭环的承重点，但强制一步一定会掉转化。这个取舍需要 A/B 才能定，当时只能凭判断。
Gap 03 没考虑版权边界。用影视片段做二创涉及授权，这在真实产品里是设计前置条件，会直接影响模板库怎么建、哪些片段可用。当时完全没触及。
